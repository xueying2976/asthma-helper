# Asthma Helper v7 — complete native integration source

This version is additive to the final editor v6, not Kiro's v5 adapter. It preserves all five tabs, structured record CRUD, source selection, confirmed reference rebuilding, v5 medicine/reminder behavior, offline Noto Sans SC and its OFL license. The browser workbench remains unchanged and bilingual; the native trial remains English-only. No publication, backend, accounts, analytics, remote AI, new health permissions or patient data were added.

## More → Prepare for a doctor visit

Choose 7 days (default), 30 days or an inclusive custom calendar interval up to 90 days. Default excludes today and ends yesterday. Selecting partial today in custom mode sets the end date to today; disabling it resets the end to yesterday. The whole inclusive interval, including a selected partial day, is limited to 90 calendar days. Swift remains the authority on the resulting range and timezone.

Notes default to none; only explicitly selected note IDs are sent. Questions can be added, edited and removed. Blank questions are omitted; nonblank question text is not rewritten. Editing any option invalidates the preview/token. Snapshot or insights read-back changes also invalidate the preview. In native mode no demo report replaces a failed read. Without a native bridge, the browser retains the original synthetic workbench and no doctor report/PDF export is simulated.

## Exact native boundary — no v6 replacement

The existing v1 envelope and request IDs are unchanged. Two methods are added to `BRIDGE_METHODS`, `BridgeParams` and `BridgeResults` in `src/lib/aeriday/nativeBridge.ts`:

```ts
getDoctorSummary({
  range: { kind: 'last7' | 'last30' | 'custom', start?: ISO, end?: ISO, includeToday?: boolean },
  selectedNoteIds?: string[], patientQuestions?: string[]
}) -> { summary: DoctorVisitSummary, token: string }
exportDoctorSummary({ token: string, format: 'pdf' }) -> { ok: true, format: 'pdf' }
```

Custom request `start` and `end` are **inclusive local calendar midnights serialized to ISO strings**, not date-only strings; request `end` is not response `endExclusive`. This is the wire interpretation of the requested inclusive calendar UI. Swift must interpret those instants as inclusive dates in its report timezone; verify device/report timezone agreement locally. Requests use **`selectedNoteIds`**, not `selectedNoteIDs`. Results use **`metricID`**, never `metricId`. These endpoints allow 60 seconds, including native share UI; timeout cannot establish whether an already-open share sheet completed.

`src/lib/aeriday/doctorSummary.ts` is the exact validated report boundary. It is separate from the unchanged v6 insight schemas; report state/regimen/purpose/metricID are strings, not v6 enums. All count fields are finite numbers (not forcibly integers). `schemaVersion` is a number, not restricted to 1. Required arrays remain required even when empty. Swift nullable optional keys are accepted both **omitted and null**, with no synthesized values.

| Summary group | Exact accepted keys |
|---|---|
| Header | `schemaVersion, generatedAt, timeZone, isDemo, recordRevision` |
| range | `start, endExclusive, completedDays, includesPartialToday, timeZoneIdentifier, firstInclusiveDay, lastInclusiveDay` |
| reportingCoverage | `expectedDays, knownSymptomDays, missingWearableDays` |
| symptoms[] | `field, knownDays, positiveDays, unansweredDays` |
| medicationLogs[] | `label, medicationName?, regimen, purpose, eventCount, loggedDays, totalAmount?, unit?` |
| peakFlow | `validReadingCount, minValue?, maxValue?, unit:'L/min', percentOfConfirmedBestRange?` (number array) |
| wearableContext[] | `metricID, unit, usableDays, missingDays, sources:string[], observedMin?, observedMax?, incompatibleSources` |
| personalChanges[] | `metricID, state, referenceStart?, referenceEnd?, referenceValidDays, recentValidDays, observedDifference?, unit, ruleVersion` |
| Other | `personalChangesOmittedReason?, selectedNotes:[{id,date,text}], patientQuestions:string[], limitations:string[]` |

Dates are ISO strings with offsets. Nullable fields shown with `?` above can also be null. Selected notes use report `text`, while snapshot notes use `note`; no field remapping occurs inside the native report. Invalid responses or unrenderable range timezone show a read error, not a guessed report. No compatibility downgrade to an incomplete v5 DTO exists.

## Preview and sharing

Preview order is header/range/timezone/generatedAt/demo, coverage, symptoms, medication logs, peak flow, wearable context, personal changes, selected notes, questions, limitations. Values, native names/amounts/units/state strings, native omission reason and text are preserved. Missing values show “Not supplied,” never zero. Denominators, unanswered days, missing days, source incompatibility and personal-reference dates are visible. Percentages only render the already supplied confirmed-best array; no JS percent calculation, zones, clinical scores, diagnosis or dose advice. Generated/date labels use the supplied range timezone; exact interval ISO values remain available.

On `report_stale`, the token/old preview are discarded, the UI says **“Records changed — regenerate”**, and calls `getDoctorSummary` again with the current options. Regeneration failure offers Retry preview. Cancellation errors (codes containing `cancel`) retain the preview and say sharing was canceled; other failures do not claim export success. A successful native response only confirms the **share request** completed, not that a PDF was delivered or saved. Swift owns token validation, record revision checking, PDF generation, share UI and all patient analysis.
